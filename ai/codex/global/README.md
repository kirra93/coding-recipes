# Глобальная настройка Codex

Для Windows используйте [отдельное руководство с командами PowerShell](README.windows.md).

Этот каталог хранит переносимые инструкции, роли агентов и навыки для работы в разных проектах. Файлы здесь являются шаблонами: Codex использует глобальные настройки из домашнего каталога после их установки.

Руководство проверено 29 сентября 2026 года. Доступность моделей и параметры могут зависеть от версии CLI, приложения и аккаунта.

## 1. Что где хранить

| Что | Глобальный путь | Когда использовать |
| --- | --- | --- |
| Модель, усилие рассуждения, согласования, MCP | `~/.codex/config.toml` | Личные значения по умолчанию для всех проектов |
| Общие инженерные правила | `~/.codex/AGENTS.md` | Устойчивые предпочтения: границы задачи, проверка, формат результата |
| Пользовательские агенты | `~/.codex/agents/*.toml` | Отдельные роли с конкретным результатом |
| Пользовательские навыки | `~/.agents/skills/<name>/SKILL.md` | Повторяемые специализированные процессы |
| Хуки | `~/.codex/hooks.json` | Механические действия по событиям, например уведомление |
| Разрешения команд | `~/.codex/rules/*.rules` | Точные решения о запуске команд вне песочницы |
| Настройки одного проекта | `<repo>/.codex/config.toml` | Инструменты и параметры конкретного репозитория |
| Правила одного проекта | `<repo>/AGENTS.md` | Архитектура, команды и документация проекта |

CLI и IDE используют общие слои конфигурации. Параметры запуска, доверенные проектные настройки и выбранный профиль могут перекрывать глобальные значения; административные ограничения действуют отдельно. См. [порядок приоритетов](https://learn.chatgpt.com/docs/config-file/config-basic).

Не переносите в глобальные правила конкретные пути, команды тестов или обязательное чтение документации одного проекта. В частности, блок «This project uses codebase-memory-mcp» в [шаблоне AGENTS.md](AGENTS.md) нужно адаптировать перед установкой: глобально предпочтителен индекс, **когда он доступен и актуален**, с переходом к исходникам при недостаточных результатах.

## 2. Проверить текущую установку и сделать резервную копию

Начните с терминала:

```bash
codex --version
codex --help
codex mcp list
```

Перед ручными изменениями сохраните только затрагиваемые настройки. Следующий блок рассчитан на Bash; он не копирует файлы авторизации и секреты:

```bash
codex_backup="$HOME/.codex/backups/manual-$(date +%Y%m%d-%H%M%S)"
mkdir -p "$codex_backup"
for codex_item in config.toml AGENTS.md agents hooks.json rules; do
  if [ -e "$HOME/.codex/$codex_item" ]; then
    cp -a "$HOME/.codex/$codex_item" "$codex_backup/"
  fi
done
if [ -d "$HOME/.agents/skills" ]; then
  cp -a "$HOME/.agents/skills" "$codex_backup/user-skills"
fi
printf 'Резервная копия: %s\n' "$codex_backup"
```

Сохраните этот путь для отката. Резервную копию с личными настройками не добавляйте в репозиторий.

## 3. Выбрать базовые параметры

Откройте `~/.codex/config.toml` и измените нужные ключи, сохранив остальные разделы. Не заменяйте весь файл примером ниже. Корневые ключи TOML должны находиться **до** первого заголовка таблицы, иначе они попадут в предыдущий раздел.

Пример повседневной настройки:

```toml
model = "gpt-6-sol"
model_reasoning_effort = "medium"
approval_policy = "on-request"
approvals_reviewer = "user"
sandbox_mode = "workspace-write"
web_search = "live"

[agents]
max_concurrent_threads_per_session = 3
```

`Sol / medium` — отправная точка для ежедневной разработки, а не обязательная модель. Для сложного архитектурного решения сравните более сильную модель или усилие на реальной задаче. Проверяйте доступность через `/model`; не повышайте усилие всех ролей автоматически. См. [выбор моделей](https://developers.openai.com/api/docs/guides/model-selection).

`workspace-write` задаёт границы доступа. `on-request` управляет запросами согласования, а `approvals_reviewer` выбирает проверяющего: человека (`user`) или отдельного агента (`auto_review`). Auto Review добавляет модельные вызовы и сохраняет границы песочницы. Сохранённый default не описывает все ранее открытые сессии: проверяйте выбранный режим в интерфейсе и фактические настройки. См. [Auto Review](https://learn.chatgpt.com/docs/sandboxing/auto-review).

Лимит `3` в `[agents]` относится к дочерним потокам и не включает основной. Он не заставляет Codex делегировать работу.

## 4. Установить общие инструкции

Из корня `coding-recipes`, после просмотра и адаптации шаблона:

```bash
mkdir -p "$HOME/.codex"
cp -i ai/codex/global/AGENTS.md "$HOME/.codex/AGENTS.md"
```

Если глобальный файл уже есть, удобнее перенести отдельные нужные правила вручную. Сохраняйте правила, которые меняют полезное поведение: узкая область работы, повторное использование найденного контекста, проверки по риску, честный отчёт о результатах.

Проектные источники истины остаются в проекте. Не требуйте полного плана, архитектурного исследования и отдельного review для каждой маленькой правки.

## 5. Добавить агентов и навыки

Актуальный механизм пользовательских агентов — отдельные TOML-файлы в `~/.codex/agents/`. Обязательны `name`, `description` и `developer_instructions`; поле `name` задаёт имя роли. Подробности: [пользовательские агенты](https://learn.chatgpt.com/docs/agent-configuration/subagents).

В этом каталоге есть следующие роли:

| Роль | Задача |
| --- | --- |
| `explorer` | Найти и описать нужный путь исполнения |
| `architect` | Разрешить конкретный выбор границ, владения или жизненного цикла |
| `implementer` | Сделать ограниченный патч по установленным требованиям |
| `reviewer` | Найти подтверждённые дефекты в изменениях |
| `security_reviewer` | Проверить изменённую границу доверия |
| `docs_researcher` | Проверить внешнюю техническую неопределённость по первичным источникам |
| `docs_writer` | Обновить необходимую документацию |

Модели и усилие указаны в [самих файлах](agents/architect.toml). Перед установкой проверьте каждый выбранный файл: роль может переопределять модель родителя, а живые настройки разрешений родительской сессии могут перекрывать её defaults. Наличие `sandbox_mode = "read-only"` в шаблоне не заменяет проверку реальных разрешений.

Установите выбранную роль, например архитектора:

```bash
mkdir -p "$HOME/.codex/agents"
cp -i ai/codex/global/agents/architect.toml "$HOME/.codex/agents/architect.toml"
```

Для проверки явно попросите: «Запусти агента architect для одного выбора X. Нужен краткий вывод, без правки файлов». Один агент должен давать преимущество перед работой основного: независимый взгляд или параллельное исследование. Само наличие роли не гарантирует запуск: текущие локальные версии используют делегирование по прямому запросу либо применимым инструкциям проекта или навыка.

В [skills/](skills/README.md) лежат восемь инженерных навыков. Копируйте целый выбранный каталог, включая `references/`:

```bash
mkdir -p "$HOME/.agents/skills"
cp -ai ai/codex/global/skills/debugging-investigation "$HOME/.agents/skills/"
```

Существующие версии сравните перед слиянием; не удаляйте сторонние навыки из общего каталога. Навык можно проверить явным вызовом `$debugging-investigation` в подходящей задаче. Маленькая правка может обойтись без навыков и дочерних агентов. См. [навыки](https://learn.chatgpt.com/docs/build-skills).

## 6. Подключить MCP и проверить разрешения

### 6.1. Установить codebase-memory-mcp — индексатор кода

Для работы с этими инженерными шаблонами настройте индексатор: он даёт Codex поиск символов и связей вызовов через граф. Установка сервера глобальная, первая индексация выполняется отдельно для каждого репозитория. Это отдельный инструмент, не встроенная память Codex.

Скачайте и просмотрите [официальный установщик](https://raw.githubusercontent.com/DeusData/codebase-memory-mcp/main/install.sh), затем запустите его:

```bash
cbm_setup_dir="$(mktemp -d)"
curl -fsSL https://raw.githubusercontent.com/DeusData/codebase-memory-mcp/main/install.sh \
  -o "$cbm_setup_dir/install.sh"
less "$cbm_setup_dir/install.sh"
bash "$cbm_setup_dir/install.sh" --skip-config
"$HOME/.local/bin/codebase-memory-mcp" --version
```

`--skip-config` пропускает автоматическую настройку клиентов. Без него установщик может менять MCP, инструкции, навыки и хуки обнаруженных клиентов. Здесь подключаем сервер явно, сохраняя контроль над глобальными правилами. Если бинарник уже установлен, сначала проверьте его версию и путь; повторная установка нужна только при намеренном обновлении.

Подключите бинарник к Codex по абсолютному пути:

```bash
codex mcp add codebase-memory -- "$HOME/.local/bin/codebase-memory-mcp"
codex mcp list
```

Если запись `codebase-memory` уже существует, сначала проверьте её через `codex mcp get codebase-memory`, сравните путь и исправьте существующую настройку вместо создания второго сервера. При нестандартном каталоге установки укажите свой путь. Перезапустите клиент и проверьте сервер и его инструменты через `/mcp`.

### 6.2. Построить индекс и проверить, что он используется

Откройте Codex из корня рабочего репозитория и отправьте:

```text
Настрой индекс текущего репозитория через codebase-memory-mcp.
Определи абсолютный путь корня и вызови index_repository с repo_path.
Дождись завершения, затем проверь list_projects и index_status.
Выбери проект по результату list_projects и передавай его в запросах,
чтобы не смешивать данные разных репозиториев.
Найди существующую функцию через search_graph, прочитай её через
get_code_snippet и проверь связи через trace_path, если они есть.
Сверь найденный фрагмент с текущим файлом. Покажи статус, имя проекта
и пример найденного символа. Исходники и конфигурацию не меняй.
```

Наличие сервера в `/mcp` ещё не означает, что репозиторий проиндексирован. Критерий готовности: индексация завершилась без ошибки, нужный проект виден в списке, граф находит известный символ, а фрагмент совпадает с текущим файлом. Для репозитория только с документацией выбирайте проверку доступных файлов: связи функций могут отсутствовать.

По [документации индексатора](https://github.com/DeusData/codebase-memory-mcp#readme), после первой индексации работает автоматическое обновление. После смены ветки или крупных изменений проверьте актуальность; в новых версиях есть `check_index_coverage` для нужных путей. Если индекс устарел, запросите обновление через `index_repository`. Не запускайте полную индексацию перед каждым поиском. Доступные инструменты зависят от установленной версии.

В глобальном `AGENTS.md` задайте правило: при доступном актуальном графе начинать поиск кода с `search_graph`, связи проверять через `trace_path`, реализацию читать через `get_code_snippet`. Для конфигурации, строк, неохваченных файлов или недоступного графа использовать обычный поиск и прямое чтение. Сам индекс не доказывает корректность кода и не заменяет проверку файлов перед правкой.

### 6.3. Другие MCP и разрешения

Пример read-only сервера официальной документации:

```bash
codex mcp add openaiDeveloperDocs --url https://developers.openai.com/mcp
codex mcp list
```

Эта команда меняет конфигурацию. Для ежедневного обращения к нему задайте соответствующую маршрутизацию в глобальных инструкциях или используйте навык OpenAI Docs. См. [Docs MCP](https://developers.openai.com/learn/docs-mcp).

Не копируйте абсолютные пути бинарников и настройки встроенных браузерных инструментов с чужой машины. Проектный MCP с особым runtime лучше настраивать в проекте. `required = true` делает недоступность сервера причиной отказа запуска/возобновления; применяйте это только при реальной обязательности. Политики инструментов и остальные параметры описаны в [справочнике конфигурации](https://learn.chatgpt.com/docs/config-file/config-reference).

Перед сохранением широкого разрешения проверьте его границы без выполнения самой команды:

```bash
codex execpolicy check --pretty \
  --rules "$HOME/.codex/rules/default.rules" \
  -- docker compose down -v
```

Пример предполагает, что файл правил существует. `check` только вычисляет решение. Если правило разрешает больше, чем вы намеревались, сузьте его или выберите `prompt`. См. [правила команд](https://learn.chatgpt.com/docs/agent-configuration/rules).

## 7. Память, плагины и уведомления

Память стоит настраивать после проверки её реального влияния. Отключение генерации и отключение использования — разные операции; не удаляйте память ради эксперимента. Названия параметров сверяйте со [справочником](https://learn.chatgpt.com/docs/config-file/config-reference).

Плагины устанавливайте и подключайте штатными средствами клиента. Они могут добавлять навыки, MCP и хуки; проверяйте включённое состояние и доступность в новой сессии. Редкое использование само по себе не повод для удаления.

Для уведомлений можно использовать `~/.codex/hooks.json`. Команда должна существовать в текущей ОС, а неменеджируемый хук требует доверия к точному определению. Не переносите Linux-команду `notify-send` на другую платформу без адаптации. См. [хуки](https://learn.chatgpt.com/docs/hooks).

## 8. Проверить результат и откатить при необходимости

После изменения начните новую сессию; при необходимости перезапустите клиент. В CLI проверьте `/status`, `/model`, `/permissions`, `/mcp` и явно испытайте установленный навык или роль.

Синтаксис TOML можно проверить Python 3.11+:

```bash
python3 - <<'PY'
from pathlib import Path
import tomllib
files = [Path.home() / '.codex/config.toml']
files += sorted((Path.home() / '.codex/agents').glob('*.toml'))
for path in files:
    with path.open('rb') as stream:
        tomllib.load(stream)
    print('TOML OK:', path)
PY
```

Это проверка синтаксиса, не поддерживаемости всех ключей или доступности модели. Окончательная проверка — запуск клиента и реальная задача.

Меняйте один слой за раз. На 2–3 задачах фиксируйте качество первой реализации, исправления после review, время, паузы согласования, токены и компакции. Инструкции по сбору — в [руководстве CodeBurn](../../codeburn/README.md).

Для отката восстановите **только изменённые файлы** из сохранённой копии. Например, для конфигурации, если переменная ещё содержит путь:

```bash
cp -i "$codex_backup/config.toml" "$HOME/.codex/config.toml"
```

Затем начните новую сессию и снова проверьте эффективные настройки. Новые файлы, которых не было в копии, требуют отдельного решения об удалении; полное восстановление каталога может затереть посторонние изменения.
