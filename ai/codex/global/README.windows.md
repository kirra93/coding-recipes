# Глобальная настройка Codex на Windows

Основной сценарий — **VS Code с официальным расширением Codex**. Начните с быстрого старта ниже. Для установки индексатора понадобится PowerShell; подключение MCP и запуск индексации выполняются в панели Codex внутри VS Code. Подробные команды для ручной настройки приведены во второй части. Руководство сверено с официальной документацией 29 сентября 2026 года; на реальной Windows-машине примеры не запускались.

Скопируйте файлы из `ai/codex/global` на свой компьютер по следующим путям. `%USERPROFILE%` — ваша папка пользователя, например `C:\Users\Ivan`; путь можно вставить в адресную строку Проводника.

| Что скопировать из этого каталога | Куда положить на Windows |
| --- | --- |
| Файл `AGENTS.md` | `%USERPROFILE%\.codex\AGENTS.md` |
| Выбранные файлы из `agents/`, например `architect.toml` | `%USERPROFILE%\.codex\agents\architect.toml` |
| Каталоги навыков из `skills/` целиком, например `debugging-investigation/` | `%USERPROFILE%\.agents\skills\debugging-investigation\` |

Создайте недостающие папки. Копируйте содержимое `agents/` и каталоги навыков без дополнительного уровня `global` или `skills`. У каждого навыка внутри должен остаться `SKILL.md` и вложенные материалы. Если файлы уже есть, сохраните копию и сравните их перед заменой. При заданном `CODEX_HOME` используйте его вместо `%USERPROFILE%\.codex` для инструкций и агентов. Назначение этих файлов кратко объяснено [в конце руководства](#what-is-included).

## Быстрый старт: VS Code + Codex + индексатор

<a id="vscode-setup"></a>

### Шаг 1. Установить VS Code и расширение Codex

1. Скачайте Windows-установщик с [сайта Visual Studio Code](https://code.visualstudio.com/) и установите редактор. Если VS Code уже есть, пропустите установку.
2. Откройте VS Code. Нажмите **Ctrl + Shift + X** — появится раздел **Extensions / Расширения**.
3. Найдите `Codex` и выберите официальное расширение от **OpenAI**. Чтобы выбрать нужное среди похожих, используйте кнопку **Install the extension** на [официальной странице Codex для IDE](https://learn.chatgpt.com/docs/codex/ide). Нажмите **Install / Установить** и при необходимости перезапустите VS Code.
4. Нажмите значок **Codex** на боковой панели. Если значка нет, нажмите **Ctrl + Shift + P**, найдите **Codex: Open Codex Sidebar** и выполните команду.
5. В панели Codex выберите вход через ChatGPT, завершите его в браузере и вернитесь в VS Code.
6. Через **File → Open Folder / Файл → Открыть папку** выберите корень своего проекта. Откройте файл и отправьте в панели Codex: «Объясни этот файл, ничего не меняй».

Основная работа дальше идёт в **панели Codex внутри VS Code**. Расширение и терминальный CLI — два способа работы: отдельная установка CLI для этого быстрого старта не нужна. Если хотите также запускать Codex в терминале, см. [установку CLI](#cli-install).

<a id="where-to-type"></a>

### Шаг 2. Понять, куда вставлять текст

| Что показано в инструкции | Куда вставлять |
| --- | --- |
| Блок `powershell` | В окно PowerShell, затем нажать Enter |
| Поля подключения MCP | В форму добавления сервера в настройках Codex |
| Промпт обычным текстом | В чат Codex внутри открытого проекта |
| Блок `toml` из подробной части | В файл `config.toml`, открытый редактором |

Удобнее работать прямо в VS Code: откройте **Terminal → New Terminal / Терминал → Создать терминал**. Если выбрана другая оболочка, через стрелку рядом с кнопкой **+** выберите **PowerShell**. Это обычный терминал, не поле чата Codex.

Также можно открыть отдельное окно: нажмите **Пуск**, введите **PowerShell** и откройте **Windows PowerShell** или **PowerShell** обычным запуском. В Windows Terminal выберите вкладку PowerShell. Перед строкой ввода обычно написано `PS C:\...>`. Сами символы `PS ...>` копировать не нужно. Здесь устанавливается глобальный инструмент, поэтому текущая папка терминала не важна.

Блоки вставляйте целиком, по очереди, в **одно окно**: следующий блок использует переменные предыдущего. При ошибке остановитесь на этом шаге. В чат Codex команды установки вставлять не нужно.

<a id="indexer-install"></a>

### Шаг 3. Установить индексатор в PowerShell

Если индексатор уже установлен, переходите к шагу 4. Для новой установки вставьте блок ниже. Он скачает официальный скрипт и откроет его в Блокноте для просмотра:

```powershell
$ErrorActionPreference = 'Stop'
$cbmSetupDir = Join-Path ([System.IO.Path]::GetTempPath()) ('cbm-setup-' + [guid]::NewGuid())
New-Item -ItemType Directory -Path $cbmSetupDir | Out-Null
$cbmInstaller = Join-Path $cbmSetupDir 'install.ps1'
Invoke-WebRequest -Uri 'https://raw.githubusercontent.com/DeusData/codebase-memory-mcp/main/install.ps1' -OutFile $cbmInstaller
notepad $cbmInstaller
```

После просмотра вернитесь в **то же окно PowerShell** и вставьте:

```powershell
Unblock-File -LiteralPath $cbmInstaller
& $cbmInstaller --skip-config
$cbmBinary = Join-Path $env:LOCALAPPDATA 'Programs\codebase-memory-mcp\codebase-memory-mcp.exe'
& $cbmBinary --version
if ($LASTEXITCODE -ne 0) { throw 'Не удалось проверить установленный индексатор' }
Write-Output "Путь для формы MCP: $cbmBinary"
```

Дождитесь завершения и номера версии. Скопируйте напечатанный путь — он нужен в следующем шаге. `--skip-config` оставляет подключение и инструкции на ваше усмотрение. Источник: [официальный установщик индексатора](https://raw.githubusercontent.com/DeusData/codebase-memory-mcp/main/install.ps1). Если Windows блокирует `.ps1`, см. раздел 6.1 ниже.

<a id="indexer-gui"></a>

### Шаг 4. Подключить индексатор через интерфейс

В **панели расширения Codex в VS Code** откройте **меню с шестерёнкой → MCP servers → Add server**. Если работаете в отдельном приложении, путь: **Settings / Настройки → MCP servers → Add server**. Подключение через эти формы описано в [официальной инструкции MCP](https://learn.chatgpt.com/docs/extend/mcp). Названия могут отличаться в зависимости от версии и языка интерфейса.

Заполните форму:

| Поле | Значение |
| --- | --- |
| Name / Имя | `codebase-memory` |
| Transport / Тип | `STDIO` |
| Command / Команда | Полный путь, напечатанный в шаге 3, без окружающих кавычек |
| Arguments / Аргументы | Оставить пустым |
| Environment / Переменные окружения | Оставить пустым |

Уже существующий сервер откройте для проверки, не добавляйте второй. Нажмите **Save / Сохранить**, затем **Restart / Перезапустить**; в IDE — **Restart extension**. Проверьте подключение в списке MCP расширения. В приложении или CLI также можно использовать `/mcp`. При нестандартной установке укажите фактический путь к `codebase-memory-mcp.exe`.

<a id="first-index"></a>

### Шаг 5. Построить индекс сообщением в чате

Откройте новую локальную сессию для нужной папки проекта и отправьте **в чат Codex**:

```text
Проиндексируй текущий репозиторий через codebase-memory-mcp.
Вызови index_repository с абсолютным путём корня проекта.
Дождись завершения, проверь list_projects и index_status.
В нужном проекте найди известную функцию через search_graph,
прочитай get_code_snippet и сверь с текущим файлом.
Покажи результат проверки. Исходники и конфигурацию не меняй.
```

Готово, когда Codex показывает завершённую индексацию и найденный символ из вашего проекта. Для каждого нового репозитория повторяйте этот шаг. Если в проекте только документы, попросите проверить доступные файлы вместо функции.

<a id="quick-instructions"></a>

### Шаг 6. Добавить общие правила через Проводник

Нажмите **Win + R**, вставьте `%USERPROFILE%\.codex` и нажмите Enter. Если папки нет, создайте `.codex` в своей папке пользователя. При заданном `CODEX_HOME` используйте его каталог вместо стандартного.

Если `AGENTS.md` уже существует, сначала сделайте его копию и объедините правила вручную. Для новой установки скопируйте сюда `AGENTS.md` из полученного каталога `global`. В Блокноте можно отредактировать инструкции; не допускайте имени `AGENTS.md.txt`. Сохраните в UTF-8. Блок про граф должен применяться, когда индексатор доступен и индекс актуален; при сбое должен оставаться обычный поиск по файлам.

Начните новую сессию Codex и попросите: «Прочитай глобальные инструкции и найди один символ проекта через граф». Модель и разрешения выбирайте в интерфейсе клиента. Дополнительные агенты, навыки и ручной `config.toml` можно настроить позже по разделам ниже.

## Подробная настройка и команды для CLI

Эта часть нужна для ручного управления конфигурацией, установки ролей и навыков, диагностики и отката. Команды выполняйте в PowerShell; блоки с переменными — в одном окне. Для команд `codex ...` должен быть установлен Codex CLI (раздел 1).

<a id="clients"></a>

## 1. Установить VS Code, расширение и CLI

Основной вариант — нативная Windows, VS Code и PowerShell. Установка редактора и расширения описана в [шаге 1 быстрого старта](#vscode-setup). Для нового окружения предпочтительна Windows 11. WSL2 выбирайте, когда проект и инструменты уже работают в Linux; настройки этой среды отдельные. См. [Windows sandbox](https://learn.chatgpt.com/docs/windows/windows-sandbox).

<a id="cli-install"></a>

### 1.1. Установить Codex CLI в терминал VS Code

CLI пригодится для терминальных сессий, проверки версии и команд `codex mcp ...`. Чат расширения продолжает быть основным интерфейсом. Ниже используем npm-вариант из [официальной инструкции CLI](https://learn.chatgpt.com/docs/codex/cli) — вкладка **npm**.

1. Установите **Node.js LTS** с [официального сайта Node.js](https://nodejs.org/). В установщике оставьте компонент npm и добавление в PATH. Если Node.js уже есть, сначала проверьте его командами ниже.
2. После установки полностью закройте и снова откройте VS Code, чтобы он получил новый PATH.
3. Откройте **Terminal → New Terminal** и выберите **PowerShell**. Выполните:

```powershell
node --version
npm.cmd --version
```

4. Если обе команды показали версии, установите CLI в том же терминале:

```powershell
npm.cmd install -g @openai/codex
if ($LASTEXITCODE -ne 0) { throw 'Установка Codex CLI завершилась с ошибкой' }
codex.cmd --version
```

5. Терминал VS Code обычно открывается в папке проекта. Проверьте её и запустите CLI:

```powershell
Get-Location
codex.cmd
```

Если открыта другая папка, сначала перейдите в корень проекта: `Set-Location -LiteralPath 'C:\Projects\my-project'`, заменив путь своим. При первом запуске выберите **Sign in with ChatGPT** и завершите вход в браузере, если CLI его запросит. Затем отправляйте задачи прямо в терминальную сессию. Для возврата к расширению используйте боковую панель Codex.

Имена `npm.cmd` и `codex.cmd` в этом примере обходят блокировку npm-файлов `.ps1` политикой PowerShell. Далее в руководстве написано `codex`; при такой блокировке заменяйте его на `codex.cmd`. Изменять политику выполнения для всех пользователей не требуется.

<a id="cli-check"></a>

### 1.2. Проверка, обновление и дополнительные инструменты

Проверка CLI в PowerShell:

```powershell
Get-Command codex.cmd
codex.cmd --version
codex.cmd --help
```

Обновление версии, установленной через npm:

```powershell
npm.cmd install -g @openai/codex@latest
```

Расширение обновляется отдельно через **Extensions** в VS Code. Установка нового CLI не гарантирует обновление встроенного runtime расширения. MCP-конфигурация CLI и расширения общая при одном пользователе, `CODEX_HOME` и среде Windows; после изменений перезапустите расширение.

Git нужен для работы с репозиториями: если его нет, установите [Git for Windows](https://git-scm.com/downloads/win). При наличии `winget` Git и Node.js можно установить из PowerShell вместо скачивания установщиков:

```powershell
winget install --id Git.Git -e
winget install --id OpenJS.NodeJS.LTS -e
```

Выполняйте только недостающие установки. Отдельное [приложение для Windows](https://learn.chatgpt.com/docs/windows/windows-app) остаётся дополнительным вариантом; для работы через VS Code оно не обязательно.

<a id="backup"></a>

## 2. Подготовить пути и резервную копию

Распакуйте полученный каталог или откройте копию репозитория. Укажите путь к папке, где лежат этот README, `AGENTS.md`, `agents/` и `skills/`:

```powershell
$ErrorActionPreference = 'Stop'
$templatePath = 'C:\Users\YOUR_USER\Downloads\global'
$codexUserPath = Join-Path $env:USERPROFILE '.codex'
if ($env:CODEX_HOME) {
    $codexUserPath = $env:CODEX_HOME
}
$skillUserPath = Join-Path $env:USERPROFILE '.agents\skills'

if (-not (Test-Path (Join-Path $templatePath 'AGENTS.md'))) {
    throw 'Исправьте templatePath: в указанной папке нет AGENTS.md'
}
New-Item -ItemType Directory -Path $codexUserPath -Force | Out-Null
$backupPath = Join-Path $codexUserPath ('backups\manual-' + (Get-Date -Format 'yyyyMMdd-HHmmss') + '-' + [guid]::NewGuid().ToString('N'))
New-Item -ItemType Directory -Path $backupPath | Out-Null
foreach ($item in @('config.toml', 'AGENTS.md', 'agents', 'hooks.json', 'rules')) {
    $source = Join-Path $codexUserPath $item
    if (Test-Path $source) {
        Copy-Item -LiteralPath $source -Destination $backupPath -Recurse
    }
}
if (Test-Path $skillUserPath) {
    Copy-Item -LiteralPath $skillUserPath -Destination (Join-Path $backupPath 'user-skills') -Recurse
}
Write-Output "Копия сохранена: $backupPath"
```

Замените `templatePath` своим путём. Обычно Codex хранит настройки в `%USERPROFILE%\.codex`; если задан `CODEX_HOME`, проверьте, что клиент использует именно его. Сохраните напечатанный путь резервной копии для отката. Скрипт не копирует файлы авторизации и секретов.

<a id="config"></a>

## 3. Настроить config.toml

Откройте файл в редакторе:

```powershell
notepad (Join-Path $codexUserPath 'config.toml')
```

Для новой установки сохраните следующий пример как `config.toml`, а не `config.toml.txt`, в UTF-8. Если файл уже существует, измените только соответствующие ключи и сохраните остальные разделы. Корневые параметры должны стоять **до** заголовков таблиц; не добавляйте вторую таблицу `[windows]` или `[agents]`, если она уже есть.

```toml
model = "gpt-6-sol"
model_reasoning_effort = "medium"
approval_policy = "on-request"
approvals_reviewer = "user"
sandbox_mode = "workspace-write"
web_search = "live"

[windows]
sandbox = "elevated"

[agents]
max_concurrent_threads_per_session = 3
```

Это пример для старта. Модель должна быть доступна в вашем аккаунте: проверьте `/model` или список моделей в клиенте. Не переносите чужие настройки провайдера, абсолютные Linux-пути и список доверенных проектов. Слои конфигурации описаны в [Config basics](https://learn.chatgpt.com/docs/config-file/config-basic).

`workspace-write` ограничивает область работы, `on-request` включает запросы согласования, `user` адресует их вам. Auto Review можно проверить отдельно через `approvals_reviewer = "auto_review"`: это другой проверяющий с дополнительными модельными вызовами, а не расширение доступа. См. [Auto Review](https://learn.chatgpt.com/docs/sandboxing/auto-review).

`[windows].sandbox = "elevated"` выбирает реализацию песочницы. При первой настройке Codex может запросить разрешение администратора; это не означает, что для ежедневной работы нужно отключить песочницу или постоянно запускать клиент от администратора. Если настройка недоступна или блокируется политикой компьютера, предусмотрен более слабый fallback `unelevated`. Причину сбоя и разрешённые варианты проверьте по [Windows sandbox](https://learn.chatgpt.com/docs/windows/windows-sandbox).

<a id="instructions"></a>

## 4. Установить общие инструкции

Сначала откройте полученный `AGENTS.md`. Адаптируйте блок «This project uses codebase-memory-mcp»: если такого MCP у вас нет, уберите именно этот блок или замените безусловное требование условием «когда индекс доступен и актуален». Не добавляйте глобально команды и архитектуру одного проекта.

После просмотра установите файл с подтверждением:

```powershell
Copy-Item -LiteralPath (Join-Path $templatePath 'AGENTS.md') `
    -Destination (Join-Path $codexUserPath 'AGENTS.md') -Confirm
```

При существующем файле сравните правила и перенесите нужные вручную. Все файлы, которые редактируете, сохраняйте в UTF-8.

<a id="agents-skills"></a>

## 5. Добавить выбранных агентов и навыки

Для начала достаточно одного агента и одного подходящего навыка. Модели в шаблонах ролей могут отличаться от основной модели: просмотрите TOML перед установкой и выберите доступные вам значения. Например, архитектурная роль лежит в `agents/architect.toml`.

```powershell
$agentDir = Join-Path $codexUserPath 'agents'
New-Item -ItemType Directory -Path $agentDir -Force | Out-Null
Copy-Item -LiteralPath (Join-Path $templatePath 'agents\architect.toml') `
    -Destination (Join-Path $agentDir 'architect.toml') -Confirm
```

Для навыка копируйте весь каталог с вложенными материалами:

```powershell
New-Item -ItemType Directory -Path $skillUserPath -Force | Out-Null
$skillTarget = Join-Path $skillUserPath 'debugging-investigation'
if (Test-Path $skillTarget) {
    throw 'Навык уже установлен: сначала сравните существующий каталог с шаблоном'
}
Copy-Item -LiteralPath (Join-Path $templatePath 'skills\debugging-investigation') `
    -Destination $skillTarget -Recurse
```

Повторите для выбранных файлов и каталогов, не заменяя весь пользовательский набор. Семь ролей и восемь навыков описаны в [общем руководстве](README.md). Форматы и пути также приведены в официальных документах [Subagents](https://learn.chatgpt.com/docs/agent-configuration/subagents) и [Build skills](https://learn.chatgpt.com/docs/build-skills).

<a id="mcp"></a>

## 6. Подключить нужные MCP

Не копируйте чужой `config.toml` целиком: Linux-бинарники, пути расширений и внутренние браузерные runtime могут не существовать на Windows.

<a id="mcp-install-details"></a>

### 6.1. Установить codebase-memory-mcp

Индексатор нужен для поиска символов и связей кода через граф. Установите сервер один раз для пользователя Windows, затем индексируйте каждый рабочий репозиторий. Это отдельный инструмент, не встроенная память Codex.

Установите бинарник по **шагу 3 быстрого старта**. Подключить его можно через форму из шага 4 или, если установлен CLI, командой в PowerShell:

```powershell
$cbmBinary = Join-Path $env:LOCALAPPDATA 'Programs\codebase-memory-mcp\codebase-memory-mcp.exe'
codex mcp add codebase-memory -- "$cbmBinary"
codex mcp list
```

Выберите один способ подключения: GUI или CLI. При нестандартном каталоге измените путь к бинарнику.

`--skip-config` пропускает автоматическую настройку клиентов: без него установщик может менять MCP, инструкции, навыки и хуки. Подключение к Codex здесь выполняется явно. Если бинарник уже установлен, сначала проверьте его версию и путь; не обновляйте его случайно. При существующей записи используйте `codex mcp get codebase-memory` и исправьте её путь вместо создания дубликата.

При блокировке `.ps1` проверьте `Get-ExecutionPolicy -List` и разрешённый на вашей машине способ запуска. `Unblock-File` снимает метку скачанного файла, но не отменяет Execution Policy. На управляемом компьютере соблюдайте политику администратора; альтернативный способ установки описан в [репозитории индексатора](https://github.com/DeusData/codebase-memory-mcp#readme).

Абсолютный путь бинарника позволяет запускать MCP без зависимости от обновления PATH в уже открытом клиенте. Перезапустите Codex и проверьте `/mcp`: сервер должен подключиться и предоставить инструменты.

<a id="index-details"></a>

### 6.2. Выполнить первую индексацию

Откройте Codex из корня своего проекта. Отправьте:

```text
Настрой индекс текущего репозитория через codebase-memory-mcp.
Определи абсолютный Windows-путь корня и вызови index_repository с repo_path.
Дождись завершения, затем проверь list_projects и index_status.
Выбери проект по результату list_projects и передавай его в запросах.
Найди известную функцию через search_graph, прочитай get_code_snippet
и проверь связи через trace_path, если они есть.
Сверь фрагмент с текущим файлом. Покажи статус, имя проекта и символ.
Исходники и конфигурацию не меняй.
```

Готовность проверяется результатом индексации и чтением существующего символа из нужного проекта. Один успешный `/mcp` не проверяет индекс. В репозитории только с документацией связи функций могут отсутствовать.

Согласно [документации индексатора](https://github.com/DeusData/codebase-memory-mcp#readme), после первой индексации действует автоматическое обновление. После смены ветки или крупных изменений проверьте актуальность; новые версии предоставляют `check_index_coverage` для выбранных путей. При устаревшем индексе запросите `index_repository`, не запускайте полную индексацию перед каждым поиском.

Добавьте в глобальный `AGENTS.md` правило: доступный актуальный граф использовать первым для поиска кода и связей, затем сверять реализацию с файлами. Для конфигурации, строк, неохваченных файлов или недоступного графа оставьте обычный поиск. Набор инструментов зависит от версии сервера.

Если работаете в WSL, устанавливайте Linux-бинарник внутри WSL по [общему руководству](README.md). Windows MCP и Linux MCP должны получать пути своей среды; не передавайте `C:\...` Linux-серверу.

<a id="other-mcp"></a>

### 6.3. Остальные MCP

Пример подключения сервера официальной документации:

```powershell
codex mcp add openaiDeveloperDocs --url https://developers.openai.com/mcp
codex mcp list
```

Команда `add` меняет конфигурацию. См. [Docs MCP](https://developers.openai.com/learn/docs-mcp).

Если сервер запускается через npm/npx и не стартует, сначала проверьте, что команда доступна в среде клиента: `Get-Command npx.cmd`. Имя команды и аргументы выбирайте по инструкции конкретного сервера. Пути Windows в TOML удобно записывать как `C:/Tools/server.exe` либо строкой в одинарных кавычках: `'C:\Tools\server.exe'`.

Плагины подключайте штатными средствами клиента; Linux-хук с `notify-send` на Windows не переносите. Набор уведомлений можно настроить позже.

<a id="verify"></a>

## 7. Проверить работу

Перезапустите клиент или начните новую сессию. В CLI из папки своего проекта выполните `codex`, затем проверьте:

- `/status` — текущую конфигурацию;
- `/model` — модель и усилие;
- `/permissions` — режим доступа;
- `/mcp` — доступные серверы.

В приложении проверьте соответствующие элементы настроек. Выбор разрешений в текущей сессии и настройки проекта могут отличаться от defaults файла.

Для первой проверки попросите: «Прочитай инструкции проекта и объясни одну точку входа. Файлы не меняй». Для роли — «Запусти architect для одного архитектурного выбора; верни краткий вывод». Для навыка в задаче с неясным дефектом явно укажите `$debugging-investigation`.

Убедитесь, что Codex использует ваши файлы, корректно вызывает роль и навык и не делает лишних шагов. На следующих задачах меняйте один слой за раз и оценивайте результат, а не только расход токенов.

<a id="troubleshooting"></a>

## 8. Частые проблемы и откат

| Симптом | Что проверить |
| --- | --- |
| Команда не найдена | Новый терминал после установки, PATH, `Get-Command codex`; для npm — `codex.cmd` |
| Настройки не изменились | `CODEX_HOME`, эффективные настройки сессии, проектный `.codex/config.toml`, перезапуск клиента |
| Недоступна модель агента | `model` и `model_reasoning_effort` именно в TOML выбранной роли |
| Ошибка песочницы | UAC, политики компьютера и инструкции Windows sandbox; не заменяйте диагностику Full Access |
| Русский текст повреждён | Кодировка UTF-8; в Windows PowerShell 5.1 не используйте обычный `>` для создания русских документов |

Для отката восстановите только изменённый файл, когда `$backupPath` ещё содержит путь копии:

```powershell
Copy-Item -LiteralPath (Join-Path $backupPath 'config.toml') `
    -Destination (Join-Path $codexUserPath 'config.toml') -Confirm
```

Если исходного файла в копии нет, это была новая установка: решение об удалении нового файла принимайте отдельно. Не восстанавливайте всю `.codex` поверх новых сессий и посторонних изменений.

<a id="wsl"></a>

### Если работаете в WSL2

Нативный Windows-клиент и Codex внутри WSL по умолчанию используют разные домашние каталоги. В WSL настройки находятся в Linux `~/.codex` и `~/.agents/skills`; там применимы Bash-команды [общего руководства](README.md). Среда агента и оболочка встроенного терминала выбираются отдельно. Начните с раздельных настроек, чтобы Windows-пути и Linux-команды не смешивались. Подробнее: [настройка WSL](https://learn.chatgpt.com/docs/windows/wsl).

<a id="what-is-included"></a>

## Зачем нужны AGENTS.md, агенты и навыки

| Часть настройки | Назначение |
| --- | --- |
| `AGENTS.md` | Общие правила работы Codex во всех проектах: как исследовать код, делать правки, проверять результат и использовать индексатор. Особенности конкретного проекта задавайте в его собственном `AGENTS.md`. |
| `agents/*.toml` | Роли дочерних агентов с отдельными инструкциями и настройками модели. Например, `explorer` исследует код, `architect` разбирает выбор решения, `implementer` вносит правки, `reviewer` проверяет результат. |
| `skills/<имя>/SKILL.md` | Сценарии для определённых задач: расследование ошибки, проектирование границы API, проверка изменений и другие. Вложенные `references/` содержат дополнительные материалы. |

Наличие роли не запускает её автоматически. Например, можно попросить: «Запусти reviewer для проверки этих изменений». Навык можно вызвать явно в сообщении: `$debugging-investigation` вместе с описанием ошибки. Для простой правки отдельная роль или навык могут не понадобиться.

После копирования начните новую сессию Codex. Роли описаны в [общем руководстве](README.md), а инструкции каждого навыка находятся в соответствующем `skills/<имя>/SKILL.md`.
