# Дополнение к аудиту: контекстные дампы с пользовательскими оценками

Используйте вместе с [основным промптом](audit-prompt.md), если вы действительно сохранили и оценили эти сессии. Для нового набора без меток сначала запишите оценки в `session-notes.ru.md` по [руководству диагностики](diagnostics.md).

---

В каталоге диагностики есть репрезентативные контекстные дампы. Трактуй имена как обратную связь от меня:

- `context-good.json`: результат сессии считаю успешным.
- `context-bad.json`: результат заметно хуже ожидаемого.
- `context-expensive.json`: выбрана по расходу ресурсов; это не оценка качества.
- `context-recent-heavy.json`: недавняя сессия выбрана по отношению эффективного контекста к кэшированным токенам.
- `context-crosswords.json`: сессия другого проекта для сравнения.

Сначала проверь наличие файлов и сравни измеримое поведение. Не выводи причины из имён. Если файла или пользовательской оценки нет, явно отметь это.

Обрати внимание на:

- частоту вызовов shell и объём результатов инструментов;
- повторное исследование и чтение тех же файлов;
- компакции и потерю установленного контекста;
- повторные полные проверки без новых изменений;
- связь навыков с качеством результата, без вывода о причинности из одной корреляции;
- долю Auto Review и практическую пользу его решений;
- присутствие пользовательских агентов в сыром происхождении сессий, даже если CodeBurn их не показывает.
