# Диагностика Codex с CodeBurn

Руководство для ручного сбора данных и проверки глобальной настройки Codex по реальным сессиям. Команды сверены с локальной версией CodeBurn **0.9.25** 29 сентября 2026 года. Перед использованием другой версии проверьте `--help`.

Связанные документы:

- [Настройка глобального Codex](../codex/global/README.md).
- [Промпт для аудита и одобренных изменений](audit-prompt.md).
- [Подсказка по размеченным контекстам](doctor-prompt.md) — дополнительный материал, если такие файлы действительно есть.

## 1. Проверить инструменты и полноту истории

Предполагается, что Codex и CodeBurn уже установлены и доступны в терминале:

```bash
command -v codeburn
codeburn --version
codeburn doctor --provider codex --json
codex --version
```

`doctor` проверяет обнаружение и разбор журналов. Сверьте пути, количество найденных файлов, ошибки парсинга и пропуски. Успешная проверка выборки не гарантирует полноту всей истории. Если старые журналы удалены или перенесены, месячный отчёт не восстановит их автоматически.

## 2. Быстро посмотреть использование

```bash
codeburn report --period week --provider codex
codeburn models --period week --provider codex
codeburn sessions --period week --provider codex --no-pager
codeburn optimize --period week --provider codex
```

Последняя команда только выдаёт предложения. Для диагностики не используйте `optimize --apply`, `--yes` или `--auto-revert`: вывод инструмента ещё не является обоснованным изменением настройки.

## 3. Создать воспроизводимый снимок

Запустите следующий блок **из корня coding-recipes**. Он создаёт новый каталог с меткой времени в `tmp/`, который исключён из Git. Команды рассчитаны на Bash. Сохраняйте значение `diagnostic_dir` для следующих блоков.

```bash
mkdir -p tmp
diagnostic_dir="$(mktemp -d tmp/codex-diagnostics-$(date +%Y%m%d-%H%M%S)-XXXXXX)"
(
  set -e
  date -Is > "$diagnostic_dir/collected-at.txt"
  codeburn --version > "$diagnostic_dir/codeburn-version.txt"
  codex --version > "$diagnostic_dir/codex-version.txt"
  codeburn doctor --provider codex --json > "$diagnostic_dir/doctor-codex.json"
  codeburn report --period week --provider codex --format json > "$diagnostic_dir/report-week.json"
  codeburn report --period 30days --provider codex --format json > "$diagnostic_dir/report-30days.json"
  codeburn audit --period week --provider codex --format json > "$diagnostic_dir/audit-week.json"
  codeburn models --period week --provider codex --by-task --format json > "$diagnostic_dir/models-by-task-week.json"
  codeburn models --period week --provider codex --by-agent --format json > "$diagnostic_dir/models-by-agent-week.json"
  codeburn sessions --period week --provider codex --format json > "$diagnostic_dir/sessions-week.json"
  codeburn sessions --period week --provider codex --by-work-unit --format json > "$diagnostic_dir/sessions-work-units-week.json"
  codeburn optimize --period week --provider codex --format json > "$diagnostic_dir/optimize-week.json"
  codeburn context --provider codex --list > "$diagnostic_dir/context-list.txt"
  printf 'Снимок: %s\n' "$diagnostic_dir"
)
```

Переменная `diagnostic_dir` остаётся в текущем терминале. Для следующего терминала задайте её вручную напечатанным путём. При ошибке блок прекращает сбор: такой каталог не считайте полным снимком.

Для сравнения изменений предпочтителен фиксированный интервал. Вместо `--period week` подставьте в соответствующие команды, например, `--from 2026-09-23 --to 2026-09-28`; названия файлов и заметку о периоде тоже скорректируйте. Все сравниваемые отчёты должны иметь одинаковый provider, период и настройки часового пояса. Для явного выбора зоны предусмотрен глобальный параметр `codeburn --timezone Europe/Moscow ...`.

Активные сессии продолжают пополняться во время сбора. Снимок не атомарный: закончите сравниваемые задачи перед сбором либо зафиксируйте, что данные предварительные.

Проверьте JSON и исключение из Git:

```bash
python3 - "$diagnostic_dir" <<'PY'
import json, sys
from pathlib import Path
files = sorted(Path(sys.argv[1]).glob('*.json'))
for path in files:
    with path.open() as stream:
        json.load(stream)
print('JSON прочитаны:', len(files))
PY
git check-ignore -v "$diagnostic_dir/report-week.json"
```

Диагностика может содержать названия проектов, пути и сведения о работе. Не публикуйте её целиком без просмотра.

## 4. Выбрать сессии и сохранить контекст

Откройте `sessions-week.json` или табличный вывод `sessions`. Выберите несколько разных задач: успешную по вашей оценке, требующую переделки, дорогую, длинную и контрольную из другого проекта. Полный `sessionId` надёжнее сокращённого префикса.

Замените значение ниже настоящим ID:

```bash
session_id='ВСТАВЬТЕ-ПОЛНЫЙ-ID'
codeburn context "$session_id" --provider codex --json \
  > "$diagnostic_dir/context-current.json"
codeburn context "$session_id" --provider codex --full --json \
  > "$diagnostic_dir/context-full.json"
```

При сборе нескольких сессий меняйте имена файлов. Без `--full` анализируется текущий контекст после компакции; с `--full` — вся история. Контекстные токены CodeBurn являются экспериментальной оценкой, их нельзя напрямую приравнивать к сумме биллинговых токенов за все модельные вызовы.

Рядом создайте `session-notes.ru.md`: ID, задача, ваша оценка результата, причина выбора, существенные коррекции и изменения модели/режима. Метка `context-bad.json` означает отзыв о результате, а не установленную причину. Без оценки пользователя не называйте сессию плохой по одной стоимости.

## 5. Как читать отчёты

| Файл / показатель | Что проверять |
| --- | --- |
| `doctor-codex.json` | Источники, полнота, ошибки и пропуски |
| `report-week.json` | Модели, категории работы, инструменты, навыки, доля Auto Review |
| `audit-week.json` | Исходные поля токенов, reasoning, кэш, использованные ставки |
| `sessions-week.json` | Концентрация расхода в отдельных задачах |
| `context-full.json` | Компакции, результаты инструментов, метаданные, доля вывода относительно контекста |
| `context-current.json` | Что осталось в контексте после последней компакции |
| Сырые журналы | Фактическая конфигурация ходов, вложенные MCP, происхождение агентов и причины отказов |

Стоимость CodeBurn — расчёт инструмента, который нужно сверить со ставками в `audit`; она не доказывает реальные списания или точное потребление квоты подписки. Высокая доля кэша не делает длинную сессию бесплатной.

Категории действий и привязка затрат к навыку не доказывают причинность: сложные задачи сами чаще вызывают навыки. Не складывайте показатели, которые могут пересекаться. Повторный тест может быть оправдан новым патчем; проверяйте порядок событий.

### Auto Review

В строке `Codex Auto Review` измерьте вызовы, входные/выходные/кэшированные токены и расчётную стоимость. Посчитайте доли от общего количества вызовов и стоимости. Затем проверьте реальные решения: доля дешёвых чтений, отклонения, причины и сколько ручных пауз он заменил.

Auto Review проверяет согласования, а пользовательский агент `reviewer` проверяет код: это разные роли. Режим `user` заменяет автоматическую проверку человеком, сохраняя песочницу; он не гарантирует удобства на задачах с большим количеством запросов. Подробнее: [официальная документация Auto Review](https://learn.chatgpt.com/docs/sandboxing/auto-review).

## 6. Когда сверять сырые журналы

В CodeBurn 0.9.25 `models --by-agent` описан как разрез для Claude; Codex может попадать в `main`. В нашем снимке 28 сентября пустые поля `mcpServers` и `subagents` не отразили вложенные вызовы и дочерние потоки. Не считайте пустое поле доказательством отсутствия активности.

Путь конкретного JSONL можно получить из `session.filePath` контекстного отчёта. Анализируйте выбранные журналы, а не весь домашний каталог. На текущей версии локальных журналов полезны следующие поля; формат может измениться:

- `session_meta.payload.thread_source`: `user`, `subagent`, `guardian_review`;
- `session_meta.payload.source.subagent.thread_spawn`: роль и родитель дочернего потока;
- `turn_context.payload`: модель, усилие рассуждения, `approvals_reviewer` и разрешения;
- `response_item`: вызовы и результаты инструментов; MCP может быть вложен в текст вызова `exec`;
- сообщения решения guardian: `outcome`, риск и оценка авторизации, когда такие записи доступны.

При подсчёте не дублируйте события `response_item` и `event_msg`, описывающие одну операцию. Не суммируйте накопительные счётчики токенов как независимые вызовы. У дочернего потока проверяйте также имя файла и родительскую связь: поле `session_id` не всегда достаточно для различения.

## 7. Исследование и изменение с Codex

Скопируйте [audit-prompt.md](audit-prompt.md) в новую сессию и подставьте абсолютные пути репозитория и свежей диагностики.

Порядок работы:

1. Только чтение настроек и анализ снимка; отчёт и предложения на русском.
2. Выбрать отдельные пронумерованные изменения.
3. После явного одобрения — резервная копия затронутых файлов, точные правки и diff.
4. Начать новую сессию и проверить фактические настройки.
5. Измерить 2–3 реальные задачи, затем оставить изменение или откатить.

Не меняйте сразу модели, инструкции, навыки, делегирование и согласования: после такого эксперимента будет трудно определить причину результата. Сравнивайте качество и стоимость завершённой задачи, а не число вызовов навыков или агентов.
